# 课程项目组队匹配系统（TeamMatch）—— 前端对接文档

> **文档版本**：v1.1（与后端代码同步）
> **适用对象**：前端开发（成员A）
> **后端Base URL**：`http://localhost/backend`

---

## 一、全局约定

### 1.1 统一响应格式

所有接口均返回以下JSON结构：

```json
{
    "code": 200,
    "message": "success",
    "data": {...}
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | HTTP状态码，200表示成功 |
| `message` | string | 提示信息，可直接展示给用户 |
| `data` | mixed | 响应数据体，可能是对象、数组或null |

### 1.2 HTTP状态码速查

| 状态码 | 含义 | 触发场景 | 前端处理建议 |
|--------|------|----------|-------------|
| **200** | 成功 | 请求正常处理 | 取 `data` 使用 |
| **400** | 参数错误 | 字段缺失、格式不对、业务校验失败 | 提示 `message` 给用户 |
| **401** | 未登录 | Session过期或未登录 | 跳转登录页 |
| **403** | 无权限 | 非组长操作了组长专属功能 | 提示 `message` 给用户 |
| **404** | 资源不存在 | 项目/用户等不存在 | 提示 `message` 给用户 |
| **405** | 方法不允许 | 用了GET调POST接口 | 检查请求方式 |
| **500** | 服务器错误 | 数据库连接失败等 | 提示「服务器异常」 |

### 1.3 请求约定

| 项目 | 约定 |
|------|------|
| Content-Type | `application/json` |
| 字符编码 | UTF-8 |
| 认证方式 | **Cookie 自动携带**（同域部署时前端无需手动处理） |
| 跨域凭证 | 前端需设置 `withCredentials: true` |
| 跨域头 | 后端已设置 `Access-Control-Allow-Origin: *` |

### 1.4 前端请求封装示例（JavaScript / jQuery）

```javascript
const API_BASE = 'http://localhost/backend';

// GET 请求
function apiGet(path, params = {}) {
    const query = new URLSearchParams(params).toString();
    const url = `${API_BASE}${path}${query ? '?' + query : ''}`;
    return fetch(url, {
        method: 'GET',
        credentials: 'include'
    }).then(res => res.json());
}

// POST 请求
function apiPost(path, body = {}) {
    return fetch(`${API_BASE}${path}`, {
        method: 'POST',
        credentials: 'include',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(body)
    }).then(res => res.json());
}

// PUT 请求
function apiPut(path, body = {}) {
    return fetch(`${API_BASE}${path}`, {
        method: 'PUT',
        credentials: 'include',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(body)
    }).then(res => res.json());
}

// DELETE 请求
function apiDelete(path, body = {}) {
    return fetch(`${API_BASE}${path}`, {
        method: 'DELETE',
        credentials: 'include',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(body)
    }).then(res => res.json());
}
```

### 1.5 前端全局拦截器建议

```javascript
/**
 * 统一响应拦截
 * 建议封装到所有API请求的 .then() 链中
 */
function handleResponse(res) {
    if (res.code === 200) {
        return res;          // 成功，直接返回
    }
    if (res.code === 401) {
        // 未登录：清除本地状态，跳转登录页
        localStorage.removeItem('user');
        window.location.href = '/login.html';
        return Promise.reject(new Error(res.message));
    }
    // 其他错误：抛出提示
    alert(res.message);
    return Promise.reject(new Error(res.message));
}
```

### 2.1 登录注册页

#### 接口1：用户注册

```
POST /api/user/register
```

**请求体 (JSON)**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `username` | string | 是 | 登录账号（学号），唯一 |
| `password` | string | 是 | 密码，6-20位 |
| `nickname` | string | 是 | 用户昵称 |
| `email` | string | 否 | 邮箱 |
| `phone` | string | 否 | 手机号 |

**请求示例**：
```json
{
    "username": "2024004",
    "password": "123456",
    "nickname": "赵六",
    "email": "zhaoliu@qq.com",
    "phone": "13800004444"
}
```

**成功响应 (200)**：
```json
{
    "code": 200,
    "message": "注册成功",
    "data": {
        "uid": 4,
        "username": "2024004",
        "nickname": "赵六"
    }
}
```

**错误场景**：

| code | message | 触发条件 |
|------|---------|----------|
| 400 | 用户名已存在 | 学号重复注册 |
| 400 | 密码长度必须在6-20之间 | 密码不符合要求 |
| 400 | nickname不能为空 | 昵称未填写 |

#### 接口2：用户登录

```
POST /api/user/login
```

**请求体 (JSON)**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `username` | string | 是 | 登录账号（学号） |
| `password` | string | 是 | 密码 |

**请求示例**：
```json
{
    "username": "2024001",
    "password": "123456"

```

**成功响应 (200)**：
```json
{
    "code": 200,
    "message": "登录成功",
    "data": {
        "uid": 1,
        "username": "2024001",
        "nickname": "张三",
        "email": "zhangsan@qq.com",
```

#### 接口10：审批申请（通过/拒绝）

```
PUT /api/applications/{id}/handle
```

> **需要登录 + 仅该项目的组长可操作**

**请求体 (JSON)**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | string | 是 | `"accept"` 通过 或 `"reject"` 拒绝 |

**请求示例（通过）**：
```json
{
    "action": "accept"
}
```

**成功响应 — 通过 (200)**：
```json
{
    "code": 200,
    "message": "申请已通过，成员已加入项目",
    "data": {
        "project_status_changed": false
    }
}
```

**成功响应 — 拒绝 (200)**：
```json
{
    "code": 200,
    "message": "申请已拒绝",
    "data": null
}
```

> **`project_status_changed` 说明**：
> - `false` — 项目状态未变更（还没满员）
> - `true` — 通过该申请后项目满员，状态已自动从「招募中」变为「已满」
> - 前端收到 `true` 时，应刷新项目详情并更新状态显示

**错误场景全览**：

| code | message | 说明 |
|------|---------|------|
| 400 | 申请不存在 | — |
| 400 | 该申请已处理 | 可能重复操作 |
| 400 | 项目已满员，无法通过申请 | 并发情况下先到先得 |
| 400 | action必须为accept或reject | 参数错误 |
| 401 | 请先登录 | — |
| 403 | 仅项目组长可审批申请 | 越权操作 |

## 四、前端状态管理建议

### 4.1 全局状态（localStorage 持久化）

```javascript
// 登录成功后保存
localStorage.setItem('user', JSON.stringify({
    uid: 1,
    nickname: '张三',
    username: '2024001'
}));

// 退出登录时清除
localStorage.removeItem('user');
```

### 4.2 页面间状态传递

| 场景 | 推荐方式 |
|------|----------|
| 从首页点击项目卡片 → 项目详情 | URL参数传递 `pid`：`project.html?pid=1` |
| 从项目详情 → 组长审批页 | URL参数传递 `pid`：`approval.html?pid=1` |
| 从项目详情 → 进度看板 | URL参数传递 `pid`：`progress.html?pid=1` |
| 全局用户信息 | localStorage（登录时写入，退出时清除） |

### 4.3 登录态校验

在需要登录的页面（个人中心、发布项目、审批、推荐等），页面加载时先发一个 `GET /api/user/profile` 请求：
- 返回 200 → 已登录，正常展示页面
- 返回 401 → 未登录，跳转登录页

## 五、前端常见问题FAQ

### Q1：登录后怎么保持状态？
A：后端使用 PHP Session + Cookie 机制，前端无需手动传 token。请求时设置 `credentials: 'include'` 即可。同域部署（phpStudy的WWW目录）时浏览器会自动携带Cookie。

### Q2：为什么调用接口返回 405？
A：请求方法不对。比如 `/api/user/login` 只接受 POST，不要用 GET 请求。

### Q3：DELETE 请求怎么发？
A：技能删除接口使用 DELETE 方法，请求体需要传 JSON。部分浏览器对 DELETE 的 body 支持有限，可以用 `POST /api/user/skills` 加 `_method=DELETE` 参数兜底，或直接使用 fetch/xhr。

### Q4：发布项目时需要技能ID列表，怎么获取所有可选技能？
A：从课程详情或后台获取技能标签列表。`GET /api/user/profile` 返回的 `skills` 和个人中心 `GET /api/user/skills` 返回的是用户已有技能。目前需要在前端硬编码或从数据库 skill 表查询一个技能列表接口（可联系后端补充 `/api/skills` 接口）。

### Q5：项目状态 `status` 和我的申请状态 `my_application_status` 有什么区别？
A：
- `status` 是项目自身的状态（0=招募中, 1=已满, 2=进行中, 3=已结束）
- `my_application_status` 是当前登录用户对该项目的申请状态（null/0/1/2/3）

### Q6：遇到跨域问题怎么办？
A：后端已设置 `Access-Control-Allow-Origin: *`，但前端如果是独立部署（非phpStudy同域），需要确认：
1. 前端请求是否加了 `credentials: 'include'`
2. 浏览器是否拦截了第三方Cookie（检查浏览器设置）
