## 1. 系统架构概述

### 1.1 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| **后端服务** | Python 3 + `http.server` | 单文件开发服务器，集成所有 API 逻辑 |
| **数据库** | SQLite 3（WAL模式） | 文件数据库 `_team_match.db`，线程本地连接 |
| **前端框架** | Bootstrap 4.5 + jQuery | 传统多页面应用（MPA），共 10 个页面 |
| **通信协议** | HTTP/1.1 RESTful | JSON 格式请求/响应 |
| **认证方式** | Bearer Token（MD5） | Token 存储在 `sessions` 表 |

### 1.2 服务架构图

```
浏览器（前端页面）
    │
    ├── GET  /frontend/*.html     → 静态 HTML 文件（200 + Content-Type: text/html）
    ├── GET  /frontend/css/*.css   → 样式文件
    ├── GET  /frontend/js/*.js     → JavaScript 文件（application/javascript）
    ├── GET  /frontend/lib/*       → 第三方库（Bootstrap/jQuery）
    │
    └── /api/*                     → JSON API（统一响应格式）
            │
            ├── 公开接口（无需认证）
            │   ├── POST /api/user/register
            │   ├── POST /api/user/login
            │   ├── GET  /api/courses
            │   ├── GET  /api/projects
            │   └── GET  /api/projects/{pid}
            │
            ├── 用户接口（需认证）
            │   ├── GET|PUT  /api/user/profile
            │   ├── GET|POST|DELETE /api/user/skills
            │   ├── POST /api/projects/{pid}/apply
            │   ├── GET  /api/projects/{pid}/applications
            │   ├── GET|POST|PUT /api/projects/{pid}/progress
            │   ├── PUT  /api/applications/{aid}/handle
            │   └── GET  /api/recommendations
            │
            └── 管理员接口（需 admin 角色）
                ├── GET|POST|PUT /api/admin/users
                └── GET  /api/admin/stats
```

### 1.3 前端页面清单

| 页面 | 文件 | 功能 |
|------|------|------|
| 首页/项目广场 | `index.html` | 项目浏览、筛选、搜索 |
| 登录 | `login.html` | 用户登录 |
| 注册 | `register.html` | 用户注册 |
| 项目详情 | `project.html?pid={id}` | 项目详情、成员列表、申请加入 |

## 2. 认证与授权机制

### 2.1 密码加密

- **算法**: `MD5(username + password + "team_match_salt")`
- 密码在服务端计算哈希后与数据库匹配
- 明文密码不落库，不可逆

### 2.2 Token 签发与验证

**签发流程（登录）**:
```
1. 验证用户名和密码哈希
2. 检查 is_active 状态
3. 生成 Token = MD5(uid + 当前时间戳)
4. 写入 sessions 表: INSERT INTO sessions(token, uid, username, role)
5. 返回 Token 给客户端
```

**验证流程（API 请求）**:
```
1. 读取 HTTP Header: Authorization: Bearer <token>
2. 查询 sessions 表: SELECT uid, role FROM sessions WHERE token=?
3. 获取当前用户的 uid 和 role
4. 进行权限判断
```

### 2.3 权限三级模型

| 级别 | 说明 | 适用接口 |
|------|------|----------|
| **公开** | 无需 Token | 注册、登录、课程列表、项目列表/详情 |
| **已登录** | 需要有效 Token | 个人信息、技能管理、申请、推荐等 |
| **管理员** | Token + `role='admin'` | `/api/admin/*` |

### 2.4 接口权限矩阵

| 接口 | 方法 | 公开 | 认证 | 管理员 | 特殊规则 |
|------|------|------|------|--------|----------|
| `/api/user/register` | POST | ✅ | - | - | - |
| `/api/user/login` | POST | ✅ | - | - | - |
| `/api/courses` | GET | ✅ | - | - | - |
| `/api/projects` | GET | ✅ | - | - | - |
| `/api/projects` | POST | - | ✅ | - | - |
| `/api/projects/{pid}` | GET | ✅ | - | - | 返回 `my_application_status` 仅认证用户 |
| `/api/user/profile` | GET/PUT | - | ✅ | - | 仅操作本人 |
| `/api/user/skills` | ALL | - | ✅ | - | 仅操作本人 |
| `/api/projects/{pid}/apply` | POST | - | ✅ | - | 不能申请自己的项目 |
| `/api/projects/{pid}/applications` | GET | - | ✅ | - | 仅组长可查看 |
| `/api/projects/{pid}/progress` | GET | - | ✅ | - | GET 公开，POST/PUT 仅组长 |
| `/api/projects/{pid}/progress` | POST/PUT | - | ✅ | - | 仅组长可操作 |
| `/api/applications/{aid}/handle` | PUT | - | ✅ | - | 仅项目组长可审批 |
| `/api/recommendations` | GET | - | ✅ | - | 基于个人技能匹配 |
| `/api/admin/users` | ALL | - | - | ✅ | 仅 `role='admin'` |
| `/api/admin/stats` | GET | - | - | ✅ | 仅 `role='admin'` |

## 3. 通用规范

### 3.1 请求格式

**HTTP Headers（所有 API 请求）**:
```http
Content-Type: application/json; charset=utf-8
Authorization: Bearer <token>    （认证接口必填）
```

**GET 请求参数**: 标准 URL Query String，如 `?page=1&page_size=10&cid=1`

**POST/PUT 请求体**: JSON 格式，如 `{"pname": "项目名", "cid": 1}`

### 3.2 统一响应格式

**成功响应**:
```json
{
  "code": 200,
  "message": "success 或具体提示",
  "data": { ... }
}
```

**错误响应**:
```json
{
  "code": 400,
  "message": "具体错误描述",
  "data": null
}
```

### 3.3 HTTP 状态码定义

| 状态码 | 含义 | 触发场景 |
|--------|------|----------|
| **200** | 成功 | 操作成功完成 |
| **400** | 请求参数错误 | 必填字段缺失、数据格式错误、业务规则校验失败（账户禁用、项目已满等） |
| **401** | 未登录 | Token 缺失或无效 |
| **403** | 无权限 | 非组长查看申请、非管理员访问后台、路径遍历攻击 |
| **404** | 资源不存在 | 接口路径错误、项目/用户不存在、文件不存在 |
| **405** | 方法不允许 | GET 接口用了 POST 等 |
| **500** | 服务器内部错误 | 未捕获的异常 |

### 3.4 前端状态码处理逻辑

```javascript
// 401 → 清除本地登录态，跳转到登录页
if (res.code === 401) {
    localStorage.removeItem('user');
    localStorage.removeItem('token');
    localStorage.removeItem('role');
    window.location.href = 'login.html';
    throw new Error('登录已过期');  // 阻止后续 API 调用
}
// 403 → 提示无权限
// 400 → 显示错误消息给用户
// 500 → 提示服务器错误，建议重试
```

### 3.5 日期时间格式

| 字段类型 | 格式 | 示例 |
|----------|------|------|
| 日期 (DATE) | `YYYY-MM-DD` | `2025-07-01` |
| 日期时间 (DATETIME) | `YYYY-MM-DD HH:MM:SS` | `2025-06-02 09:00:00` |
| 时间戳 (CURRENT_TIMESTAMP) | `YYYY-MM-DD HH:MM:SS` | `2026-06-15 03:30:05` |

> **注意**: SQLite 使用 `CURRENT_TIMESTAMP` 自动填充，返回的是服务器时间的字符串格式。

## 4. 数据模型定义

### 4.1 数据库表一览

| 表名 | 说明 | 主键 | 核心外键 |
|------|------|------|----------|
| `user` | 用户表 | `uid` AUTOINCREMENT | - |
| `course` | 课程表 | `cid` AUTOINCREMENT | - |
| `skill` | 技能标签表 | `sid` AUTOINCREMENT | - |
| `user_skill` | 用户-技能关联 | (`uid`, `sid`) | → user.uid, skill.sid |
| `project` | 项目表 | `pid` AUTOINCREMENT | → course.cid, user.uid |
| `project_skill` | 项目-需求技能 | (`pid`, `sid`) | → project.pid, skill.sid |
| `application` | 组队申请表 | `aid` AUTOINCREMENT | → project.pid, user.uid |
| `member` | 项目成员表 | `mid` AUTOINCREMENT | → project.pid, user.uid, UNIQUE(pid,uid) |
| `progress` | 进度节点表 | `prid` AUTOINCREMENT | → project.pid |
| `sessions` | 会话表 | `token` TEXT PK | → user.uid |

### 4.2 核心枚举值

**用户角色 (user.role)**:
| 值 | 说明 |
|----|------|
| `admin` | 系统管理员 |
| `leader` | 项目组长（由项目表/member表决定） |
| `member` | 普通用户 |

**项目状态 (project.status)**:
| 值 | 文本 | 说明 |
|----|------|------|
| `0` | 招募中 | 可申请加入 |
| `1` | 已满 | 人数已达上限或手动关闭 |
| `2` | 进行中 | 项目已启动 |
| `3` | 已结束 | 项目已完成或关闭 |

**申请状态 (application.status)**:
| 值 | 文本 | 说明 |
|----|------|------|
| `0` | 待处理 | 等待组长审批 |
| `1` | 已接受 | 申请人已加入项目 |
| `2` | 已拒绝 | 组长拒绝申请 |
| `3` | 已取消 | 申请人自行取消 |

**进度节点状态 (progress.status)**:
| 值 | 文本 |
|----|------|
| `0` | 待完成 |
| `1` | 已完成 |

**账号状态 (user.is_active)**:
| 值 | 说明 |
|----|------|
| `1` | 启用 |
| `0` | 禁用（无法登录） |

**软删除标识 (user.is_deleted / project.is_deleted / course.is_deleted)**:
| 值 | 说明 |
|----|------|
| `0` | 正常（默认） |
| `1` | 已删除（查询时自动过滤） |

**技能分类 (skill.category)**:
| 值 | CSS类名 |
|----|---------|
| `技术` | `skill-tech` |
| `设计` | `skill-design` |
| `管理` | `skill-mgmt` |
| `其他` | `skill-other` |

**技能熟练度 (user_skill.proficiency)**:
| 范围 | 展示 |
|------|------|
| `1-5` | ⭐ 星级 |

### 4.3 实体关系摘要

```
user ──1:N──> member ──N:1──> project ──N:1──> course
 │               │                 │
 ├──1:N──> user_skill ──N:1──> skill
 │               │                 │
 ├──1:N──> application ──N:1──> project_skill
 │                               
 └──1:N──> progress (通过project)
```

## 5. 接口详细说明

### 5.1 用户认证接口

#### 5.1.1 用户注册

```
POST /api/user/register
认证: 无需
```

**请求体**:
```json
{
  "username": "2024001",         // 必填，学号，全局唯一
  "password": "123456",           // 必填，6-20位
  "nickname": "张三",             // 必填，显示名称
  "email": "zhangsan@qq.com",     // 选填
  "phone": "13800001111"          // 选填
}
```

**响应体**:
```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "uid": 14,
    "username": "2024001",
    "nickname": "张三"
  }
}
```

**错误场景**:
| code | message | 触发条件 |
|------|---------|----------|
| 400 | 必填字段不能为空 | username/password/nickname 任一为空 |
| 400 | 密码长度6-20位 | 密码不足6位或超过20位 |
| 400 | 用户名已存在 | username 重复 |
| 405 | - | 非 POST 请求 |

---

#### 5.1.2 用户登录

```
POST /api/user/login
认证: 无需
```

**请求体**:
```json
{
  "username": "2024001",
  "password": "123456"
}
```

**响应体（成功）**:
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "uid": 2,
    "username": "2024001",
    "nickname": "张三",
    "email": "zs@qq.com",
    "phone": "13800001111",
    "avatar": null,
    "credit_score": 98,
    "role": "member",
    "is_active": 1,
    "created_at": "2026-06-15 03:30:05",
    "token": "a1b2c3d4e5f6..."
  }
}
```

**错误场景**:
| code | message | 触发条件 |
|------|---------|----------|
| 400 | 用户名或密码错误 | 用户名不存在或密码不匹配 |
| 400 | 账号已被禁用，请联系管理员 | `is_active=0` |
| 405 | - | 非 POST 请求 |

**前端使用**:
```javascript
var res = await TeamMatch.userApi.login({username: '2024001', password: '123456'});
if (res.code === 200) {
    TeamMatch.util.saveUser(res.data);  // 保存用户信息和 token 到 localStorage
}
```

## 6. 错误处理规范

### 6.1 后端错误处理流程

```
请求到达 → 路径路由匹配
    ├── 未匹配 → 404 {"code": 404, "message": "接口不存在"}
    ├── 匹配但方法不对 → 405 "Method Not Allowed"
    ├── 匹配成功
    │   ├── 参数校验失败 → 400 + 具体错误消息
    │   ├── 权限校验失败 → 403 "仅组长可查看" / "仅管理员可访问"
    │   ├── 认证校验失败 → 401 "请先登录"
    │   ├── 业务逻辑错误 → 400 + 具体业务消息
    │   └── 未捕获异常 → 500 "服务器内部错误，请稍后重试" (打印到控制台)
```

### 6.2 前端错误处理最佳实践

```javascript
async function loadData() {
    try {
        var res = await TeamMatch.projectApi.getDetail(pid);
        // 1. 检查业务状态码
        if (res.code !== 200) {
            // handleResponse 已处理 401 跳转
            if (res.code === 403) {
                showError('无权限访问');
            } else {
                showError(res.message || '操作失败');
            }
            return;
        }
        // 2. 正常渲染
        renderDetail(res.data);
    } catch (e) {
        // 3. _redirect 错误已被 request 函数抛出，此处捕获网络异常
        // 网络异常不跳转登录页，仅显示重试按钮
        if (!e._redirect) {
            showRetryButton('网络异常，请检查连接');
        }
    }
}
```

## 9. 跨域与安全规范

### 9.1 CORS 配置

所有 API 响应自动添加以下 Headers（`end_headers` 方法）:

```python
Access-Control-Allow-Origin: *
Access-Control-Allow-Credentials: true
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
```

OPTIONS 预检请求直接返回 204。

### 9.2 SQL 注入防护

所有数据库查询使用参数化查询（`?` 占位符），禁止拼接 SQL：

```python
# ✅ 正确
db.execute("SELECT * FROM project WHERE pid=? AND is_deleted=0", (pid,))

# ❌ 禁止
db.execute(f"SELECT * FROM project WHERE pid={pid}")
```

### 9.3 软删除策略

`user`、`project`、`course` 三张表使用软删除（`is_deleted=1`），所有查询必须加 `is_deleted=0` 过滤条件。

### 9.4 数据库并发

- **WAL 模式**: `PRAGMA journal_mode=WAL` — 支持一写多读并发
- **线程本地连接**: 每个线程独立 SQLite 连接，`busy_timeout=5000ms`
- **外键约束**: `PRAGMA foreign_keys = ON`

## 附录 B: 响应 code 与 HTTP Status 映射

| HTTP Status | response.code | 含义 |
|-------------|---------------|------|
| 200 | 200 | 操作成功 |
| 400 | 400 | 参数错误/业务校验失败 |
| 401 | 401 | 未登录或 Token 过期 |
| 403 | 403 | 无访问权限 |
| 404 | 404 | 接口或资源不存在 |
| 405 | 405 | HTTP 方法不允许 |
| 500 | 500 | 服务器内部异常 |

> **关键约定**: HTTP 状态码与响应体 `code` 字段保持一致，前端优先使用 `res.code` 进行判断。
