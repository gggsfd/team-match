# 课程项目组队匹配系统（TeamMatch）—— 后端开发方案

> **负责角色**：成员B（后端 + 数据库开发，技术核心）
> **开发周期**：14天
> **文档版本**：v1.0

---

## 一、项目概述与后端职责

### 1.1 系统简介

本系统面向在校学生，解决课程大作业、科创项目组队困难的痛点。学生可自主发布课程项目需求，标注项目所需技能，系统基于**技能标签重合度**智能推荐适配队友，支持学生主动申请入组、组长审批管理，最终完成项目组建与进度管控。

### 1.2 后端负责范围（成员B）

| 序号 | 核心职责 | 具体内容 |
|------|----------|----------|
| 1 | 数据库设计 | 建库建表（9张表）、ER图绘制、测试数据录入 |
| 2 | 全部API开发 | 11个RESTful接口，覆盖用户、课程、项目、申请、匹配、进度模块 |
| 3 | 智能匹配SQL | 多表JOIN聚合查询，计算技能匹配度百分比 |
| 4 | 状态机流转 | 项目状态（4态）与申请状态（4态）自动流转逻辑 |
| 5 | 权限管控 | Session登录认证、接口鉴权、角色权限校验 |
| 6 | 接口联调 | 配合前端完成数据对接、Bug修复 |

### 1.3 后端与非后端边界

```
┌──────────────┐    JSON/HTTP    ┌──────────────┐
│   前端(成员A)  │ ◄────────────► │  后端(成员B)   │
│  HTML/CSS/JS  │                │   PHP + MySQL │
└──────────────┘                 └──────┬───────┘
                                        │ SQL
                                 ┌──────▼───────┐
                                 │   MySQL 数据库  │
                                 └──────────────┘
```

- **后端只负责**：接收HTTP请求 → 业务逻辑处理 → 操作数据库 → 返回JSON数据
- **后端不负责**：HTML页面渲染、CSS样式、前端JS交互逻辑

## 二、技术栈选型

### 2.1 核心技术

| 层级 | 技术选型 | 版本要求 | 选型理由 |
|------|----------|----------|----------|
| 语言 | PHP | 7.4+ | 课程实验环境（phpStudy）标配，零框架依赖 |
| 数据库 | MySQL | 5.7+ / 8.0 | 经典关系型数据库，支持完整多表JOIN |
| 开发环境 | phpStudy | 最新版 | 一键集成 Apache + PHP + MySQL，开箱即用 |
| 接口规范 | RESTful JSON | — | 前后端分离，统一JSON数据交换格式 |

### 2.2 辅助工具

| 工具 | 用途 |
|------|------|
| Postman / Apifox | API接口调试 |
| Navicat / phpMyAdmin | 数据库可视化管理 |
| Git | 版本控制（后端代码提交） |
| VS Code | 代码编辑器 |

### 2.3 不引入额外框架的理由

- 课程设计要求掌握**原生SQL与PHP核心语法**，引入框架反而无法展示底层能力
- 系统接口数量少（11个），原生PHP路由完全够用
- 答辩时可以讲解「轻量级自建路由」的设计思路，体现工程能力
- 避免框架学习成本，保证14天内交付

### 3.1 分层架构说明

```
请求流向：index.php(路由) → middleware/Auth(鉴权) → api/*.php(控制器) → service/*.php(业务) → model/*.php(数据) → MySQL
```

| 层级 | 职责 | 不做什么 |
|------|------|----------|
| `api/` 控制器 | 接收请求参数、调用Service、返回Response | 不写SQL、不做复杂业务判断 |
| `service/` 业务层 | 核心业务逻辑、状态流转、数据校验 | 不直接操作`$_SESSION`、不直接echo |
| `model/` 数据层 | 封装SQL查询、返回数组/对象 | 不做业务判断、不处理HTTP |
| `middleware/` 中间件 | 登录校验、角色鉴权 | 不处理业务数据 |
| `util/` 工具 | 通用功能（数据库连接、响应封装、校验） | 不包含业务逻辑 |

## 四、数据库设计

### 4.1 ER实体关系总览

```
┌──────────┐       ┌──────────────┐       ┌──────────┐
│   User   │ 1───N │  UserSkill   │ N───1 │  Skill   │
└────┬─────┘       └──────────────┘       └──────────┘
     │                                           │
     │ 1                                         │ N
     │                                           │
     ▼                                           ▼
┌──────────┐       ┌──────────────┐       ┌──────────┐
│  Course  │ 1───N │   Project    │ N───N │ProjectSkill│
└──────────┘       └────┬────┬────┘       └──────────┘
                         │    │
                   1     │    │ 1
                         ▼    ▼
              ┌──────────┐  ┌──────────┐  ┌──────────┐
              │  Member  │  │Application│  │ Progress │
              └──────────┘  └──────────┘  └──────────┘
```

### 4.2 核心关系说明

| 关系 | 类型 | 说明 |
|------|------|------|
| User ↔ Skill | **多对多** | 通过 `user_skill` 中间表关联，一名学生可掌握多项技能 |
| Project ↔ Skill | **多对多** | 通过 `project_skill` 中间表关联，一个项目需要多项技能 |
| User ↔ Project（正式） | **多对多** | 通过 `member` 中间表确认正式成员关系 |
| User ↔ Project（临时） | **多对多** | 通过 `application` 表实现申请关系，审批通过后转为member |
| Course → Project | **一对多** | 一门课程下可创建多个项目 |
| Project → Progress | **一对多** | 一个项目可设置多个进度节点 |
| User → Project（创建） | **一对多** | 一个用户可作为组长创建多个项目 |

### 4.3 完整建库建表DDL

```sql
-- ============================================
-- 01_init_database.sql  建库脚本
-- ============================================
CREATE DATABASE IF NOT EXISTS team_match
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_unicode_ci;

USE team_match;


-- ============================================
-- 02_create_tables.sql  建表脚本（9张表）
-- ============================================

-- ----------------------------
-- 表1：用户表 (user)
-- ----------------------------
CREATE TABLE `user` (
    `uid`          INT           NOT NULL AUTO_INCREMENT COMMENT '用户唯一编号',
    `username`     VARCHAR(20)   NOT NULL COMMENT '登录账号（学号）',
    `password`     VARCHAR(255)  NOT NULL COMMENT '加密存储密码（MD5加盐）',
    `nickname`     VARCHAR(50)   NOT NULL COMMENT '用户昵称',
    `email`        VARCHAR(100)  DEFAULT NULL COMMENT '用户邮箱',
    `phone`        VARCHAR(20)   DEFAULT NULL COMMENT '联系电话',
    `avatar`       VARCHAR(255)  DEFAULT NULL COMMENT '头像存储地址',
    `credit_score` INT           NOT NULL DEFAULT 100 COMMENT '用户信用分，默认100',
    `created_at`   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '账号注册时间',
    `updated_at`   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最近更新时间',
    `is_deleted`   TINYINT(1)    NOT NULL DEFAULT 0 COMMENT '软删除标识：0正常/1删除',
    PRIMARY KEY (`uid`),
    UNIQUE KEY `uk_username` (`username`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户表';


-- ----------------------------
-- 表2：课程表 (course)
-- ----------------------------
CREATE TABLE `course` (
    `cid`         INT           NOT NULL AUTO_INCREMENT COMMENT '课程唯一编号',
    `cname`       VARCHAR(100)  NOT NULL COMMENT '课程名称',
    `teacher`     VARCHAR(50)   DEFAULT NULL COMMENT '任课教师姓名',
    `semester`    VARCHAR(20)   NOT NULL COMMENT '所属学期（如：2025-2026-1）',
    `description` TEXT          DEFAULT NULL COMMENT '课程简介',
    `created_at`  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `updated_at`  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最近更新时间',
    `is_deleted`  TINYINT(1)    NOT NULL DEFAULT 0 COMMENT '软删除标识',
    PRIMARY KEY (`cid`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='课程表';


-- ----------------------------
-- 表3：技能标签表 (skill)
-- ----------------------------
CREATE TABLE `skill` (
    `sid`       INT          NOT NULL AUTO_INCREMENT COMMENT '技能唯一编号',
    `sname`     VARCHAR(50)  NOT NULL COMMENT '技能名称',
    `category`  VARCHAR(20)  NOT NULL COMMENT '技能分类：技术/设计/管理/其他',
    `created_at` DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (`sid`),
    UNIQUE KEY `uk_sname` (`sname`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='技能标签表';


-- ----------------------------
-- 表4：用户技能关联表 (user_skill)
-- ----------------------------
CREATE TABLE `user_skill` (
    `uid`          INT        NOT NULL COMMENT '用户编号',
    `sid`          INT        NOT NULL COMMENT '技能编号',
    `proficiency`  TINYINT    NOT NULL DEFAULT 1 COMMENT '技能熟练度：1-5星',
    `created_at`   DATETIME   NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '关联时间',
    PRIMARY KEY (`uid`, `sid`),
    KEY `idx_uid` (`uid`),
    KEY `idx_sid` (`sid`),
    CONSTRAINT `fk_us_uid` FOREIGN KEY (`uid`) REFERENCES `user`(`uid`) ON DELETE CASCADE,
    CONSTRAINT `fk_us_sid` FOREIGN KEY (`sid`) REFERENCES `skill`(`sid`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户技能关联表';


-- ----------------------------
-- 表5：项目表 (project)
-- ----------------------------
CREATE TABLE `project` (
    `pid`          INT           NOT NULL AUTO_INCREMENT COMMENT '项目唯一编号',
    `cid`          INT           NOT NULL COMMENT '所属课程编号',
    `uid`          INT           NOT NULL COMMENT '项目组长（创建者）编号',
    `pname`        VARCHAR(100)  NOT NULL COMMENT '项目名称',
    `description`  TEXT          DEFAULT NULL COMMENT '项目详细描述',
    `max_members`  INT           NOT NULL DEFAULT 4 COMMENT '项目最大人数（含组长）',
    `status`       TINYINT       NOT NULL DEFAULT 0 COMMENT '项目状态：0招募中/1已满/2进行中/3已结束',
    `deadline`     DATE          DEFAULT NULL COMMENT '组队招募截止时间',
    `created_at`   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '项目创建时间',
    `updated_at`   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最近更新时间',
    `is_deleted`   TINYINT(1)    NOT NULL DEFAULT 0 COMMENT '软删除标识',
    PRIMARY KEY (`pid`),
    KEY `idx_cid` (`cid`),
    KEY `idx_uid` (`uid`),
    KEY `idx_status` (`status`),
    CONSTRAINT `fk_p_cid` FOREIGN KEY (`cid`) REFERENCES `course`(`cid`) ON DELETE CASCADE,
    CONSTRAINT `fk_p_uid` FOREIGN KEY (`uid`) REFERENCES `user`(`uid`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='项目表';


-- ----------------------------
-- 表6：项目需求技能表 (project_skill)
-- ----------------------------
CREATE TABLE `project_skill` (
    `pid`            INT      NOT NULL COMMENT '项目编号',
    `sid`            INT      NOT NULL COMMENT '需求技能编号',
    `required_count` INT      NOT NULL DEFAULT 1 COMMENT '该技能所需人数',
    `created_at`     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '关联时间',
    PRIMARY KEY (`pid`, `sid`),
    KEY `idx_pid` (`pid`),
    KEY `idx_sid` (`sid`),
    CONSTRAINT `fk_ps_pid` FOREIGN KEY (`pid`) REFERENCES `project`(`pid`) ON DELETE CASCADE,
    CONSTRAINT `fk_ps_sid` FOREIGN KEY (`sid`) REFERENCES `skill`(`sid`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='项目需求技能表';


-- ----------------------------
-- 表7：组队申请表 (application)
-- ----------------------------
CREATE TABLE `application` (
    `aid`         INT           NOT NULL AUTO_INCREMENT COMMENT '申请唯一编号',
    `pid`         INT           NOT NULL COMMENT '申请的项目编号',
    `uid`         INT           NOT NULL COMMENT '申请人编号',
    `message`     VARCHAR(255)  DEFAULT NULL COMMENT '申请留言/自我介绍',
    `status`      TINYINT       NOT NULL DEFAULT 0 COMMENT '申请状态：0待处理/1已接受/2已拒绝/3已取消',
    `apply_time`  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '申请提交时间',
    `handle_time` DATETIME      DEFAULT NULL COMMENT '申请处理时间',
    `created_at`  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `updated_at`  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最近更新时间',
    PRIMARY KEY (`aid`),
    KEY `idx_pid` (`pid`),
    KEY `idx_uid` (`uid`),
    KEY `idx_status` (`status`),
    UNIQUE KEY `uk_pid_uid_active` (`pid`, `uid`, `status`),
    CONSTRAINT `fk_app_pid` FOREIGN KEY (`pid`) REFERENCES `project`(`pid`) ON DELETE CASCADE,
    CONSTRAINT `fk_app_uid` FOREIGN KEY (`uid`) REFERENCES `user`(`uid`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='组队申请表';


-- ----------------------------
-- 表8：项目成员表 (member)
-- ----------------------------
CREATE TABLE `member` (
    `mid`       INT          NOT NULL AUTO_INCREMENT COMMENT '成员记录编号',
    `pid`       INT          NOT NULL COMMENT '所属项目编号',
    `uid`       INT          NOT NULL COMMENT '成员用户编号',
    `role`      VARCHAR(20)  NOT NULL DEFAULT 'member' COMMENT '角色：leader组长/member组员',
    `join_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '入组时间',
    `created_at` DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (`mid`),
    UNIQUE KEY `uk_pid_uid` (`pid`, `uid`),
    KEY `idx_pid` (`pid`),
    KEY `idx_uid` (`uid`),
    CONSTRAINT `fk_m_pid` FOREIGN KEY (`pid`) REFERENCES `project`(`pid`) ON DELETE CASCADE,
    CONSTRAINT `fk_m_uid` FOREIGN KEY (`uid`) REFERENCES `user`(`uid`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='项目成员表';


-- ----------------------------
-- 表9：进度节点表 (progress)
-- ----------------------------
CREATE TABLE `progress` (
    `prid`        INT           NOT NULL AUTO_INCREMENT COMMENT '进度节点编号',
    `pid`         INT           NOT NULL COMMENT '所属项目编号',
    `title`       VARCHAR(100)  NOT NULL COMMENT '进度节点标题',
    `description` TEXT          DEFAULT NULL COMMENT '节点详细描述',
    `status`      TINYINT       NOT NULL DEFAULT 0 COMMENT '节点状态：0待完成/1已完成',
    `deadline`    DATE          DEFAULT NULL COMMENT '节点完成截止时间',
    `created_at`  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `updated_at`  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最近更新时间',
    PRIMARY KEY (`prid`),
    KEY `idx_pid` (`pid`),
    CONSTRAINT `fk_prog_pid` FOREIGN KEY (`pid`) REFERENCES `project`(`pid`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='进度节点表';
```

### 4.5 关键索引设计说明

| 索引 | 设计理由 |
|------|----------|
| `uk_pid_uid_active(pid, uid, status)` 申请表 | 保证同一用户对同一项目**待处理申请**唯一，防止重复申请 |

| `idx_status` 项目表/申请表 | 状态字段是高频查询条件（如查询所有「招募中」项目） |
| `idx_cid` 项目表 | 按课程聚合项目时加速查询 |
| 联合主键 `(uid, sid)` | 中间表天然防重，无需额外唯一索引 |

## 六、核心业务逻辑设计

### 6.1 智能匹配推荐算法（★答辩核心亮点）

#### 6.1.1 算法原理

```
匹配度 = (学生技能 ∩ 项目需求技能) / 项目需求技能总数 × 100%

筛选条件：
1. 项目状态为「招募中」(status = 0)
2. 排除已加入的项目
3. 排除已有待处理申请的项目
4. 至少匹配上1项技能（HAVING matched_skills > 0）

排序规则：匹配度降序 → 创建时间降序
```

#### 6.1.2 完整SQL实现

```sql
-- 为指定学生（uid = ?）智能推荐高匹配度项目
SELECT
    p.pid,
    p.pname,
    p.description,
    p.max_members,
    p.deadline,
    p.created_at,
    -- 当前成员数
    (SELECT COUNT(*) FROM member m WHERE m.pid = p.pid) AS current_members,
    -- 项目所需技能总数
    COUNT(DISTINCT ps.sid) AS need_skills,
    -- 学生拥有的技能总数（仅限该项目需求范围内的）
    COUNT(DISTINCT us.sid) AS my_skills,
    -- 双方匹配的技能数量
    COUNT(DISTINCT CASE WHEN us.uid = ? THEN us.sid END) AS matched_skills,
    -- ★ 技能匹配度百分比（保留2位小数）
    ROUND(
        COUNT(DISTINCT CASE WHEN us.uid = ? THEN us.sid END) * 100.0
        / NULLIF(COUNT(DISTINCT ps.sid), 0),
        2
    ) AS match_rate,
    -- 匹配的技能名称列表（逗号分隔）
    GROUP_CONCAT(DISTINCT CASE WHEN us.uid = ? THEN s_match.sname END SEPARATOR '、') AS matched_skill_names,
    -- 未匹配的技能名称列表
    GROUP_CONCAT(DISTINCT CASE WHEN us.uid IS NULL OR us.uid != ? THEN s_all.sname END SEPARATOR '、') AS unmatched_skill_names,
    -- 课程信息
    c.cid AS course_cid,
    c.cname AS course_cname,
    -- 组长信息
    u.uid AS creator_uid,
    u.nickname AS creator_nickname
FROM project p
-- 关联课程
JOIN course c ON p.cid = c.cid AND c.is_deleted = 0
-- 关联组长
JOIN user u ON p.uid = u.uid AND u.is_deleted = 0
-- 关联项目所需技能
JOIN project_skill ps ON p.pid = ps.pid
-- ★ LEFT JOIN学生已有技能：用LEFT JOIN找到交集
LEFT JOIN user_skill us ON ps.sid = us.sid AND us.uid = ?
-- 用于获取匹配技能名称
LEFT JOIN skill s_match ON us.sid = s_match.sid
-- 用于获取全部需求技能名称
LEFT JOIN skill s_all ON ps.sid = s_all.sid
WHERE p.status = 0                           -- 仅招募中项目
  AND p.is_deleted = 0
  AND p.pid NOT IN (                         -- 排除已加入的项目
      SELECT pid FROM member WHERE uid = ?
  )
  AND p.pid NOT IN (                         -- 排除已有待处理申请的项目
      SELECT pid FROM application WHERE uid = ? AND status = 0
  )
GROUP BY p.pid, c.cid, c.cname, u.uid, u.nickname
HAVING matched_skills > 0                    -- 至少匹配1项技能
ORDER BY match_rate DESC, p.created_at DESC;
```

#### 6.1.3 算法复杂度分析

| 指标 | 数值 | 说明 |
|------|------|------|
| 时间复杂度 | O(n × m) | n=项目数，m=每个项目的平均技能数 |
| 千级数据响应 | < 50ms | 合理索引下，百级项目数据体验流畅 |
| 内存消耗 | 极低 | 全部计算在MySQL引擎层完成 |

#### 6.1.4 Service层封装（RecommendationService.php）

```php
<?php
// service/RecommendationService.php
class RecommendationService {

    /**
     * 获取当前用户的智能推荐项目列表
     * @param int $uid 当前用户ID
     * @param int|null $cid 课程筛选（可选）
     * @return array 推荐项目列表，按匹配度降序
     */
    public function getRecommendations($uid, $cid = null) {
        $db = Database::getInstance();

        $sql = "
            SELECT
                p.pid, p.pname, p.description,
                p.max_members, p.deadline, p.created_at,
                (SELECT COUNT(*) FROM member m WHERE m.pid = p.pid) AS current_members,
                COUNT(DISTINCT ps.sid) AS need_skills,
                COUNT(DISTINCT us.sid) AS my_skills,
                COUNT(DISTINCT CASE WHEN us.uid = :uid THEN us.sid END) AS matched_skills,
                ROUND(
                    COUNT(DISTINCT CASE WHEN us.uid = :uid2 THEN us.sid END) * 100.0
                    / NULLIF(COUNT(DISTINCT ps.sid), 0), 2
                ) AS match_rate,
                GROUP_CONCAT(DISTINCT CASE WHEN us.uid = :uid3 THEN sk.sname END SEPARATOR '、') AS matched_skill_names,
                c.cid AS course_cid,
                c.cname AS course_cname,
                u.uid AS creator_uid,
                u.nickname AS creator_nickname
            FROM project p
            JOIN course c ON p.cid = c.cid AND c.is_deleted = 0
            JOIN user u ON p.uid = u.uid AND u.is_deleted = 0
            JOIN project_skill ps ON p.pid = ps.pid
            LEFT JOIN user_skill us ON ps.sid = us.sid AND us.uid = :uid4
            LEFT JOIN skill sk ON us.sid = sk.sid
            WHERE p.status = 0
              AND p.is_deleted = 0
              AND p.pid NOT IN (SELECT pid FROM member WHERE uid = :uid5)
              AND p.pid NOT IN (SELECT pid FROM application WHERE uid = :uid6 AND status = 0)
        ";

        $params = [
            ':uid'  => $uid, ':uid2' => $uid, ':uid3' => $uid,
            ':uid4' => $uid, ':uid5' => $uid, ':uid6' => $uid,
        ];

        // 可选：按课程筛选
        if ($cid !== null) {
            $sql .= " AND p.cid = :cid";
            $params[':cid'] = $cid;
        }

        $sql .= "
            GROUP BY p.pid, c.cid, c.cname, u.uid, u.nickname
            HAVING matched_skills > 0
            ORDER BY match_rate DESC, p.created_at DESC
        ";

        $stmt = $db->prepare($sql);
        $stmt->execute($params);
        return $stmt->fetchAll(PDO::FETCH_ASSOC);
    }
}
```

### 6.2 项目状态自动流转（★状态机）

#### 6.2.1 状态定义

```
项目状态流转（4态）：
┌──────────┐    满员自动触发    ┌──────────┐    组长手动启动    ┌──────────┐    项目完结    ┌──────────┐
│ 0:招募中  │ ────────────────→ │ 1:已满   │ ────────────────→ │ 2:进行中  │ ────────────→ │ 3:已结束  │
└──────────┘                    └──────────┘                    └──────────┘                └──────────┘

申请状态流转（4态）：
┌──────────┐    组长通过    ┌──────────┐
│ 0:待处理  │ ────────────→ │ 1:已接受  │ → 自动加入member表
└──────────┘                └──────────┘
      │                           ↑
      │ 组长拒绝                   │ 学生重新申请
      ▼                           │
┌──────────┐     ┌──────────┐     │
│ 2:已拒绝  │     │ 3:已取消  │ ──→ 允许再次申请
└──────────┘     └──────────┘
```

#### 6.2.2 状态流转业务逻辑（ApplicationService.php）

     * @param int $aid 申请ID
     * @param int $operatorUid 操作者（组长）UID
     * @param string $action 'accept' 或 'reject'
     * @return array ['success' => bool, 'message' => string, 'project_status_changed' => bool]
     */
    public function handleApplication($aid, $operatorUid, $action) {
        $db = Database::getInstance();

        // 1. 查询申请信息，同时校验组长权限
        $sql = "SELECT a.*, p.uid AS leader_uid, p.pid, p.max_members,
                       (SELECT COUNT(*) FROM member m WHERE m.pid = p.pid) AS current_members
                FROM application a
                JOIN project p ON a.pid = p.pid
                WHERE a.aid = :aid";
        $stmt = $db->prepare($sql);
        $stmt->execute([':aid' => $aid]);
        $app = $stmt->fetch(PDO::FETCH_ASSOC);

        if (!$app) {
            return ['success' => false, 'message' => '申请不存在'];
        }

        // 2. 权限校验：仅项目组长可审批
        if ($app['leader_uid'] != $operatorUid) {
            return ['success' => false, 'message' => '仅项目组长可审批申请'];
        }

        // 3. 状态校验：仅待处理状态可审批
        if ($app['status'] != 0) {
            return ['success' => false, 'message' => '该申请已处理'];
        }

        $db->beginTransaction();
        try {
            if ($action === 'accept') {
                // 3a. 项目满员检查
                if ($app['current_members'] >= $app['max_members']) {
                    return ['success' => false, 'message' => '项目已满员，无法通过申请'];
                }

                // 3b. 更新申请状态为「已接受」
                $stmt = $db->prepare("UPDATE application SET status = 1, handle_time = NOW() WHERE aid = :aid");
                $stmt->execute([':aid' => $aid]);

                // 3c. 新增项目正式成员
                $stmt = $db->prepare("INSERT INTO member (pid, uid, role) VALUES (:pid, :uid, 'member')");
                $stmt->execute([':pid' => $app['pid'], ':uid' => $app['uid']]);

                // 3d. ★ 检查是否需要更新项目状态（满员 → 已满）
                $newCount = $app['current_members'] + 1;
                $statusChanged = false;
                if ($newCount >= $app['max_members']) {
                    $stmt = $db->prepare("UPDATE project SET status = 1 WHERE pid = :pid AND status = 0");
                    $stmt->execute([':pid' => $app['pid']]);
                    $statusChanged = true;
                }

                $db->commit();
                return [
                    'success' => true,
                    'message' => '申请已通过，成员已加入项目',
                    'project_status_changed' => $statusChanged
                ];

            } else {
                // 拒绝：更新申请状态为「已拒绝」
                $stmt = $db->prepare("UPDATE application SET status = 2, handle_time = NOW() WHERE aid = :aid");
                $stmt->execute([':aid' => $aid]);
                $db->commit();
                return ['success' => true, 'message' => '申请已拒绝'];
            }
        } catch (Exception $e) {
            $db->rollBack();
            return ['success' => false, 'message' => '操作失败：' . $e->getMessage()];
        }
    }
}

<?php
// util/Validator.php
class Validator {

    /**
     * 校验必填字段
     * @param array $data 待校验数据
     * @param array $fields 必填字段列表
     * @return array ['valid' => bool, 'message' => string]
     */
    public static function required($data, $fields) {
        foreach ($fields as $field) {
            if (!isset($data[$field]) || trim($data[$field]) === '') {
                return ['valid' => false, 'message' => "{$field}不能为空"];
            }
        }
        return ['valid' => true, 'message' => ''];
    }

    /**
     * 校验字符串长度
     */
    public static function length($value, $min, $max, $fieldName = '') {
        $len = mb_strlen($value, 'UTF-8');
        if ($len < $min || $len > $max) {
            return ['valid' => false, 'message' => "{$fieldName}长度必须在{$min}-{$max}之间"];
        }
        return ['valid' => true, 'message' => ''];
    }

    /**
     * 校验是否为有效整数
     */
    public static function isInt($value, $fieldName = '') {
        if (!is_numeric($value) || intval($value) != $value) {
            return ['valid' => false, 'message' => "{$fieldName}必须为整数"];
        }
        return ['valid' => true, 'message' => ''];
    }

    /**
     * 获取POST请求的JSON Body
     * @return array
     */
    public static function getJsonInput() {
        $input = file_get_contents('php://input');
        $data = json_decode($input, true);
        if (!is_array($data)) {
            $data = [];
        }
        return $data;
    }
}

  4. 验证不可重复申请、不可越权审批等边界情况

## 十五、风险与注意事项

| 风险点 | 应对策略 |
|--------|----------|
| PHP Session跨域问题 | 前端使用 `withCredentials: true`；后端设置 `Access-Control-Allow-Credentials: true` |
| PDO扩展未开启 | phpStudy默认已开启；若未开启需修改 `php.ini` 启用 `php_pdo_mysql.dll` |
| MySQL外键约束导致删库困难 | 测试阶段可临时关闭外键检查：`SET FOREIGN_KEY_CHECKS = 0;` |
| 匹配SQL性能问题 | 已使用LEFT JOIN + 索引优化，百级数据无压力；若数据量增大，可加Redis缓存 |
| 文件上传安全（头像） | 限制文件类型(仅jpg/png/gif)、限制大小(2MB)、重命名存储、禁止执行权限 |
| 并发申请导致超员 | 当前使用唯一索引 + 事务保护；高并发场景需加悲观锁 `SELECT ... FOR UPDATE` |
