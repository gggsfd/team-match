# TeamMatch 智能组队匹配系统 — 需求规格说明书

## 一、项目背景与目标

### 1.1 项目背景

在高校课程设计、大作业等教学环节中，学生通常需要自由组队完成项目。传统的组队方式（如微信群发布招募信息、线下口头约定）存在以下痛点：

- **信息不对称**：学生不了解有哪些项目在招募成员，也不清楚各项目需要什么技能
- **匹配效率低**：学生难以快速找到与自己技能匹配的项目
- **管理混乱**：组长需要手动统计申请、审批成员、跟踪进度，缺乏工具支持
- **缺乏全局视野**：教师和管理员无法查看整体组队情况和项目进展

### 1.2 项目目标

开发一个**智能组队匹配系统**，实现以下核心目标：

1. **信息透明**：所有项目统一展示，学生可按课程、状态、关键字快速筛选
2. **智能匹配**：基于技能标签自动计算匹配度，为学生推荐最合适的项目
3. **流程闭环**：覆盖发布项目→申请加入→审批→进度跟踪的完整组队生命周期
4. **角色分权**：管理员、组长、普通成员拥有差异化的操作权限
5. **数据沉淀**：积累课程、技能、项目数据，为后续教学分析提供基础

### 1.3 适用范围

本系统适用于高校中需要进行团队协作的课程设计、大作业、创新实践等教学场景。可为计算机相关专业的实践类课程提供组队支持。

## 二、用户角色定义

| 角色       | 标识   | 描述                                                 | 典型用户       |
| ---------- | ------ | ---------------------------------------------------- | -------------- |
| 系统管理员 | admin  | 拥有系统最高权限，负责用户管理、项目管理和全局监控   | 任课教师、助教 |
| 项目组长   | leader | 项目的创建者，负责管理项目信息、审批申请、跟踪进度   | 发起项目的学生 |
| 普通成员   | member | 已认证的学生用户，可浏览项目、提交申请、管理个人信息 | 参与课程的学生 |
| 游客       | guest  | 未登录用户，仅可浏览项目列表和课程信息               | 潜在用户       |

### 3.6 智能推荐模块

#### FR-14 个性化项目推荐

| 项目   | 描述                                                                                                                                                                                     |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 优先级 | P1（核心亮点）                                                                                                                                                                           |
| 输入   | 可选课程ID筛选                                                                                                                                                                           |
| 处理   | ① 筛选状态为「招募中」且用户未加入、未申请的项目 ② 计算每个项目的技能匹配率：matched_skills / need_skills × 100% ③ 排除匹配率为0的项目 ④ 按匹配率降序排列（同匹配率按创建时间降序） |
| 算法   | 基于Jaccard相似度的技能重叠率计算。匹配率 = 用户拥有且项目需要的技能数 ÷ 项目所需技能总数                                                                                               |
| 输出   | 推荐项目列表（含匹配率百分比、已匹配技能列表、未匹配技能列表、项目基本信息）                                                                                                             |
| 权限   | 需登录                                                                                                                                                                                   |

| 状态码   | 200=成功, 400=参数错误, 401=未登录, 403=无权限, 404=资源不存在, 405=方法不允许, 500=服务器错误 |

## 八、约束与假设

### 8.1 技术约束

| 约束     | 说明                                                 |
| -------- | ---------------------------------------------------- |
| 运行环境 | Linux服务器（Ubuntu 22.04），Nginx + PHP-FPM + MySQL |
| PHP版本  | PHP 7.4 及以上                                       |
| 数据库   | MySQL 8.0 / MariaDB，InnoDB引擎                      |
| 前端依赖 | Bootstrap 4 + jQuery（CDN引入），无需Node.js构建工具 |
| 浏览器   | Chrome 80+ / Firefox 80+ / Edge 80+ / Safari 13+     |

### 8.2 业务假设

| 假设     | 说明                                       |
| -------- | ------------------------------------------ |
| 用户身份 | 用户使用学号作为唯一用户名注册             |
| 技能体系 | 系统预置10个技能标签，覆盖常见校园项目需求 |
| 项目管理 | 项目的创建者自动成为组长，一组一组长       |
| 组队规模 | 每个项目人数上限2-20人，默认4人            |
| 密码策略 | 密码长度6-20位，使用MD5+盐哈希存储         |
| 数据保留 | 核心数据采用软删除，不物理删除数据         |
