## 二、已通过的安全检查 ✅

### 2.1 防火墙 & 端口
- UFW已激活，默认策略 `deny incoming / allow outgoing`
- 开放端口：22 (SSH)、80 (HTTP)、443 (HTTPS预留)、8080 (备用)
- MySQL(3306) 仅监听 `127.0.0.1`，未暴露外网
- UFW 同时覆盖 IPv4 和 IPv6

### 2.2 SSH 安全
- Root仅密钥登录 (`PermitRootLogin prohibit-password`)
- 密码登录已禁用 (`PasswordAuthentication no`)
- 最大认证尝试 3 次 (`MaxAuthTries 3`)
- 空密码禁止 (`PermitEmptyPasswords no`)
- X11转发已禁用 (`X11Forwarding no`)
- 空闲超时断开 (`ClientAliveInterval`)

### 2.3 Web 服务器
- 隐藏文件 (`/.`) 禁止访问
- Nginx worker 以非 root 用户运行
- Nginx 版本号隐藏 (`server_tokens off`)
- `.git` 目录未对外暴露

### 2.4 PHP 安全
- `expose_php = Off` (不暴露PHP版本)
- `display_errors = Off` (不显示错误详情)
- `log_errors = On` (错误记录到日志)
- PHP-FPM 以 `www-data` 用户运行（非root）
- 无测试/调试文件暴露

### 2.5 数据库安全
- MySQL 仅监听 127.0.0.1
- 应用用户 `teammatch` 仅允许 localhost 连接
- `root` 用户仅允许 localhost 连接
- test 数据库已删除
- 使用 `mysql_native_password` 认证

### 2.6 系统安全
- `unattended-upgrades` 已启用（自动安全更新）
- `fail2ban` 已安装运行（防暴力破解）

## 三、发现的安全风险

### 🔴 高风险

| # | 问题 | 影响 | 修复建议 |
|---|------|------|----------|
| 1 | **密码使用 MD5+SALT 哈希** | MD5已被破解，彩虹表可逆向 | 升级为 `password_hash()` (bcrypt) |
| 2 | **缺少安全响应头** | 易受XSS/点击劫持/MIME嗅探攻击 | 添加 CSP / X-Frame-Options / X-Content-Type-Options |
| 3 | **HTTP 明文传输** | 登录凭证和会话Cookie可被窃听 | 配置 Let's Encrypt HTTPS 证书 |

### 🟡 中风险

| # | 问题 | 影响 | 修复建议 |
|---|------|------|----------|
| 4 | **PHP 危险函数未禁用** | 如存在代码注入漏洞，可执行系统命令 | 禁用 `exec/system/passthru/shell_exec/popen/proc_open` |
| 5 | **PHP open_basedir 未设置** | PHP脚本可读取任意系统文件 | 限制为 `/opt/teammatch/:/tmp/` |
| 6 | **Session Cookie HttpOnly 未启用** | XSS可窃取会话Cookie | 设置 `session.cookie_httponly = 1` |
| 7 | **数据库配置文件可读** | `database.php` 权限为 755（所有人可读） | 改为 640 (`chmod 640`) |
| 8 | **敏感文件类型保护不完整** | 当前Nginx配置中 `.sql/.md/.log` 保护未生效 | 修正 Nginx location 配置 |

### 🟢 低风险

| # | 问题 | 说明 |
|---|------|------|
| 9 | 非必要服务运行 | aliyun-agent(云助手)、apache-htcacheclean、atd、chrony、tuned、udisks2 |
| 10 | IPv6 已启用 | 攻击面略有增加，UFW已覆盖但可考虑禁用 |
| 11 | 系统有 3 个待更新包 | 建议执行 `apt upgrade` |
| 12 | MySQL 端口 33060 监听 | MySQL X Protocol，如不使用建议禁用 `mysqlx=OFF` |

### ⚠️ 分享给用户的安全提示

| 场景 | 风险 | 缓解措施 |
|------|------|----------|
| 校园网内分享 | 低风险 — 相同受控网络 | 可以分享 |
| 公网直接分享 | 中风险 — 暴露在互联网 | 建议至少修复高风险项后再分享 |
| 仅小组内部使用 | 低风险 — 信任用户群体 | 当前状态可接受 |

## 四、IP 暴露风险评估

### 直接暴露 IP (8.138.252.49) 的风险

| 风险 | 可能性 | 影响 |
|------|--------|------|
| 端口扫描 | 高 | 低 — 仅4个端口开放，UFW防护 |
| SSH 暴力破解 | 中 | 低 — fail2ban已在运行，密码登录已禁用 |
| Web 应用攻击 | 中 | 中 — 缺乏WAF，缺少安全响应头 |
| DDoS 攻击 | 低 | 高 — 无CDN/流量清洗 |
| 爬虫/恶意扫描 | 高 | 低 — 仅有静态页面和API |

### 建议的缓解措施

1. **立即**: 添加安全响应头 (Nginx配置，5分钟可完成)
2. **短期**: 配置 HTTPS (Let's Encrypt 免费证书)
3. **短期**: 升级密码哈希为 bcrypt
4. **中期**: 设置 PHP open_basedir 和 disable_functions
5. **中期**: 如仅校园网使用，可通过安全组限制来源IP
6. **长期**: 前面加 CDN (Cloudflare 免费计划) 隐藏源站IP
